# ADR-003. 브라우저 워커 내부 토큰 검증

- 상태: 채택
- 결정일: 2026-08-11

## 배경

브라우저 워커는 네이버 로그인 세션과 댓글 작성 권한을 다룬다. Compose 내부 네트워크에 있더라도 인증 없이 호출되거나 개발용 기본 토큰으로 실행되면 네트워크에 접근한 다른 프로세스가 자동화를 수행할 수 있다.

인증 실패 로그에 요청 토큰을 남기면 로그 수집 시스템을 통해 자격증명이 재노출될 수도 있다.

## 결정

- `INTERNAL_API_TOKEN`이 없거나 16자 미만이면 프로세스 시작을 거부한다.
- 알려진 placeholder 값도 시작 단계에서 거부한다.
- 토큰은 길이가 같을 때 Node `crypto.timingSafeEqual`로 비교한다.
- 인증 실패 로그에는 요청 토큰이나 일부 문자열을 남기지 않는다.
- API와 워커는 같은 환경 토큰을 사용하되 사용자 Basic Auth와는 분리한다.

## 검토한 대안

### 기본 토큰으로 기동

개발 편의는 높지만 설정 누락이 정상 실행처럼 보이므로 채택하지 않았다. 명시적인 실패가 잘못된 배포를 더 빨리 드러낸다.

### 일반 문자열 비교

내부 네트워크에서 타이밍 공격 위험은 제한적이지만 표준 라이브러리로 비용 없이 더 안전한 비교가 가능해 상수 시간 비교를 선택했다.

### 요청 토큰 일부 마스킹 로그

장애 분석에 큰 도움이 되지 않으며 자격증명 단서만 남기므로 토큰 자체를 기록하지 않는다.

## 결과와 한계

- 잘못 설정된 워커는 트래픽을 받기 전에 실패한다.
- 토큰 원문이 애플리케이션 로그와 Loki에 남지 않는다.
- 공유 비밀 방식이므로 서비스별 키 회전과 중앙 비밀 관리 기능은 별도 과제다.
- 인터넷 공개 환경에서는 mTLS나 서비스 메시 같은 더 강한 서비스 인증을 검토해야 한다.
